# Инструкция по установке и использованию (antivirus)

Папка инструмента: `antivirus/`

```
tools/backup_antivirus/
├── config.php          # конфигурация (править под свой проект)
├── signatures.php      # сигнатуры вредоносного ПО
├── lib_common.php      # утилиты, логгер, email
├── lib_backup.php      # бэкап, карантин, целостность
├── lib_scanner.php     # антивирусное сканирование
├── av.php              # основной скрипт (бэкап / скан / веб)
├── restore.php         # ручное восстановление из бэкапа
├── scan_recent.sh      # bash-сканер для cron
├── logs/               # создаётся автоматически (логи)
├── data/               # создаётся автоматически (baseline целостности)
├── quarantine/         # создаётся автоматически (карантин)
└── README.md
```

## 1. Зависимости
- PHP 7.4+ с расширениями: `zip`, `pdo_mysql` (или `mysqli`), `json`, `fileinfo`.
- Для `mysqldump`/`mysql`: наличие бинарей (опционально, есть fallback на PDO).
- `bash` 4+ (для `scan_recent.sh`).
- `find`, `php` в PATH (для cron-скрипта).

Проверка на сервере:
```bash
php -m | grep -E 'zip|pdo_mysql|json|fileinfo'
```

## 2. Настройка
### Секреты: .env
Скопируйте пример и заполните свои значения:

```bash
cp .env.example .env
chmod 600 .env
```

- `AV_WEB_USER` / `AV_WEB_PASS` — логин и пароль формы входа в веб-интерфейс.
- `AV_WEB_ALLOWED_IPS` — белый список IP через запятую (пусто = любые).
- `AV_DB_*` — доступы к БД для бэкапа/восстановления.

Реальный `.env` в `.gitignore` — пароли не попадут в git.

### config.php
Откройте `config.php` и укажите:
- `site_root` — корень сайта (по умолчанию на уровень выше `tools/`).
- `db` — доступы к БД, пути к `mysqldump`/`mysql`.
- `exclude_paths` — папки, исключаемые из бэкапа и сканирования (обязательно `backup`, `tools`).
- `mail` — email администратора и SMTP (или `mail()`).
- `web.token` — **обязательно смените** `CHANGE_ME_TO_RANDOM_STRING` на случайную строку.
- `web.allowed_ips` — список разрешённых IP (можно оставить пустым, но токен обязателен).
- `scan_interval_minutes` — интервал для режима «изменённые за N минут».
- `keep_weekly` / `keep_monthly` — количество хранимых бэкапов.
- `auto_restore` — авто-восстановление заражённых файлов из бэкапа.

## 3. Права доступа
Скриптам нужно право на запись в `backup/`, `antivirus/logs/`,
`antivirus/data/`, `antivirus/quarantine/`.

```bash
chmod -R u+w antivirus
# Папку бэкапов (обычно в корне сайта) тоже делаем writable:
chmod -R u+w backup
# Скрипт cron должен быть исполняемым:
chmod +x antivirus/scan_recent.sh
# av.php / restore.php должны быть читаемы веб-сервером:
chmod 640 antivirus/*.php
```

⚠️ Безопасность: папка `antivirus/` не должна быть доступна напрямую из веба без
защиты. Если веб-сервер отдаёт `antivirus/`, добавьте в `.htaccess`/nginx запрет,
либо оставьте доступ только к `av.php`/`restore.php` по токену и ограничьте
IP через `web.allowed_ips`. Лучше всего держать `antivirus/` вне публичного каталога
и вызывать скрипты только по CLI/cron, а веб-интерфейс включать временно.

## 4. Первичная настройка baseline (целостность)
Создайте базовую линию хешей (один раз, до появления заражений):

```bash
php antivirus/av.php --baseline
```

## 5. Использование (CLI)

```bash
# Создать бэкап (файлы + БД) с ротацией
php antivirus/av.php --backup

# Сканировать файлы, изменённые за последние N минут (режим по умолчанию)
php antivirus/av.php --scan

# Полное сканирование всех файлов
php antivirus/av.php --full-scan

# Сканирование по списку путей (использует scan_recent.sh)
php antivirus/av.php --scan-list=/tmp/recent_files_12345.txt

# Отключить авто-восстановление для этого запуска
php antivirus/av.php --scan --no-restore
```

При обнаружении угрозы файл либо восстанавливается из последнего бэкапа
(если `auto_restore=true` и файл есть в бэкапе), либо помещается в `quarantine/`
и администратору отправляется критическое письмо.

## 6. Восстановление (restore.php)

```bash
# Список бэкапов
php antivirus/restore.php --list

# Восстановить файлы и БД из конкретного бэкапа
php antivirus/restore.php --restore=2026-08-22_12-00-00 --what=all

# Только файлы / только БД
php antivirus/restore.php --restore=2026-08-22_12-00-00 --what=files
php antivirus/restore.php --restore=2026-08-22_12-00-00 --what=db
```

Веб-интерфейс: `restore.php?token=ВАШ_ТОКЕН&action=list`

## 7. Cron

Регулярный бэкап (например, раз в сутки в 03:00):
```cron
0 3 * * * php /полный/путь/antivirus/av.php --backup
```

Регулярное сканирование изменённых файлов каждые 30 минут:
```cron
*/30 * * * * /полный/путь/antivirus/scan_recent.sh
```

Полное сканирование раз в неделю (воскресенье 04:00):
```cron
0 4 * * 0 php /полный/путь/antivirus/av.php --full-scan
```

## 8. Логи
- `antivirus/logs/av.log` — общий лог (ротация при 10 МБ).
- `antivirus/logs/scan_recent.log` — лог работы bash-сканера.

### Техническая часть: офлайн-лицензии продукта

Продукт использует офлайн-лицензии (Ed25519, без обращения к внешним серверам).

### Как это работает
- Ключ формата `AV1-<payload>.<подпись>` хранится в `data/license.dat`.
- Проверка: криптографическая подпись Ed25519 + срок действия.
- Без действующей лицензии **бэкапы и антивирусные проверки не выполняются**
  (CLI завершается с кодом 2, web-интерфейс редиректит на страницу «Лицензия»).
- Подделать ключ без секретного ключа владельца невозможно; правка кода
  проверки детектируется самим AV Tool (baseline целостности).
- Есть защита от отката системных часов (метка времени в `data/runtime.st`).

Публичный ключ вшит в продукт (src/Model/KeyVault.php, обфусцирован).

### Для клиента
Установите выданный ключ в веб-интерфейсе: вкладка «Лицензия» → вставить
ключ → «Установить». Статус виден на главной странице.

## 10. Примечания по безопасности
- Никогда не коммитьте реальные пароли БД в `config.php` в публичный репозиторий.
- Токен веб-доступа должен быть длинным случайным (`openssl rand -hex 32`).
- Регулярно проверяйте почту администратора на уведомления об угрозах.
- `mysqldump`/`mysql` могут требовать наличия `~/.my.cnf` или передачи пароля;
  если бинари недоступны (shared hosting), работает PDO-дамп/восстановление.
